# AI README: RYAN (foundation and front door)

Give this file to your AI assistant together with `docs/frontend/COMMON-SETUP.md` and `docs/frontend/01-ryan.md`. The AI must follow it exactly, must not invent scope, and must not touch files that are not Ryan's. If something is ambiguous, it picks the sensible default and states it in the hand-in.

## 0. Project in one paragraph
NEXORA is a SACCO (a "circle") savings and loans app. Backend: Flask + Postgres (exists). Frontend: **React 19 (JavaScript, no TypeScript) + Tailwind CSS v4 + Vite** in `frontend/`. The clickable prototype (https://claude.ai/artifact/SPDZB7PDFbRt9wDJ3cvxH7, files in `docs/frontend/prototype/`) is the visual and behavioural reference. Screenshots are in `docs/frontend/images/`. Full human docs: `docs/frontend/pdf/NEXORA-Frontend-MASTER.pdf` and `01-Ryan.pdf`.

## 1. Non-negotiable rules
1. **No AI slop**: no emoji, no decorative logos or illustrations where not needed, no lorem ipsum, no purple gradients, no filler text. Words are short, plain, specific.
2. **Units**: rem, %, vw, fr, clamp(). Tailwind spacing is rem (use it). Bare px only for 1px borders and shadows. Never `w-[300px]`. Check 375, 768, 1280 px: no sideways scroll, nothing clipped.
3. **Four states** on every list/card: loading, ready, empty, error (with Try again).
4. **No raw errors**: every failure goes through `describe()` in `lib/errors.js` and shows via `ErrorBanner`, `Field` or `ErrorPage`.
5. **Permissions, never role names**: `can('perm')`, never `role === '...'`.
6. **Money** in minor units, one `reference` per submit, reused on retry (obey even though it is Sam's area).
7. **No hex colours in `className`**. Use theme tokens: `bg-cream text-ink text-muted text-teal border-teal-2 text-err bg-pop font-serif`.
8. Buttons look and act like buttons (hover, press, focus ring, disabled). Smooth motion; respect `prefers-reduced-motion`. Back buttons only on drill-in pages, never on menu pages.
9. **Shared files are read-only**: `src/lib/*`, `src/components/*`, `src/mocks/data.js`, `src/styles/nexora*.css`, `src/styles/tailwind.css`, `src/dev/*` (except your registry), `dev.html`, `vite.config.js`. A bug in one goes to Collins; never edit it.
10. Nobody depends on anyone: work in the dev harness (`http://localhost:5173/dev.html`) with mock data, then in the real shell with `VITE_MOCK=1 npm run dev`.

## 4. Tasks and acceptance (build in this order)
**R1 Shell** (`shell-01-sidebar-desktop`): fixed sidebar at >= 64rem, sticky top bar (title, search, bell, SACCO switcher), scrolling main. Menu from `menuFor(perms)`. Coin + wordmark (`Logo.jsx`) at the top of the sidebar and on public pages ONLY. Accept: sidebar never scrolls away; short window fades and scrolls the menu inside the sidebar; z-order topbar 50, mbar 60, scrim 65, drawer 70.
**R2 Phone/tablet** (`shell-02`, `shell-03`): under 64rem the sidebar is a drawer with a scrim; Esc, scrim and menu item close it; focus moves in and back. Accept at 375/768/1280.
**R3 Router**: `react-router-dom@7`, hash-free paths, lazy `PAGE_IMPORTS` for every route; a missing page shows the placeholder "This page is being built."; `RequireAuth` sends signed-out people to `/login` and remembers the target; `guardRoute(perms,path)==='403'` shows `<ErrorPage code="403">` inside the shell; unknown path = 404. Accept: Member typing `/accounts` sees 403 with the sidebar.
**R4 Green wave** (`shell-10`, `logo-*`): curtain rises 0.9s, coin and pen-written "Nexora" show (port from `prototype/index.html` + `style.css`, search `curtain`), lifts 1.1s; about 1.7s; first load intro 4.8s; transform/opacity only; swap the page while covered; reduced motion = quick fade. **Curtain, coin and sign-in waves use theme variables** (`--cur-1/2/3`, `--disc-a/b/c`, `--ring-a/b/c`, `--wave-1/2/3`), never hex. Terracotta red, Sage green, Saffron gold, Teal 2 turquoise, Ocean blue, Rose pink, Slate grey, Ink dark green-black, Midnight dark navy; the "Nexora" writing stays visible. Accept: no flicker, no double stack, clicks during it break nothing.
**R5 Session**: `SessionProvider` gives exactly the harness shape `{user, role, perms, can, saccoId, sacco, navigate, takeOpen, toast}`. On load: tokens, then `GET /members/me`, `/members/me/saccos`, permissions (`GET /members/me/permissions?sacco_id=`; on 404/405 use `ROLES` in `perms.js`; one `if` in `api/session.js`). `login`, `logout` (`POST /auth/logout`, ignore errors, clear tokens), `onSessionEnded` shows 401. Mock: any email + password `demo`; role picker on the login page in mock mode. Accept: reload stays signed in; logout then reload = sign-in; `/loans` signed out returns to `/loans` after sign-in.
**R5b Three entries** (Master section "How people get in"): (1) Account: login, register, verify, forgot, reset = signed in, **no circle**. (2) Join: signed-in person enters phone + 6-digit code (`POST /auth/join`), keep `setup_token` in component state only, then 4-digit PIN twice (`POST /auth/join/pin`). (3) Enter your circle: PIN boxes call `POST /auth/circle-login {sacco_id,pin}` (also `/auth/sacco-login`); the answer `{ok,membership_id,role}` has no token, so keep `enteredSaccoId` in memory only (reload asks again; logout clears; switching circle asks that circle's PIN). `afterSignIn(saccos)`: platform owner to `pf-overview`; 0 circles = "You are not in a circle yet" page (plain, no logo, buttons Join with a code and Log out); 1 circle = Enter; 2+ = chooser; invited-only circle = card "Join <name>". Mock PIN `1234`; join codes `123456` ok, `000000` expired, `111111` used, `222222` burned. Handle **every row** of the R5b scenario table in `01-ryan.md` (wrong password; 5 wrong = 423 lock banner with Forgot link; unverified email resend; wrong/expired/used/burned code sentences; phone on another account; already a member; PIN step over 10 minutes goes back to step 1; PIN mismatch; wrong PIN; PIN locked 15 min; deactivated = 403; suspended = 423; reload; shared computer). Accept: a photo of each row.
**R6 Switcher, palette (Ctrl K), bell**: opaque menu with status chips; picking a circle clears `enteredSaccoId`, plays the wave, goes to `overview`; suspended circle shows 423; palette lists only `menuFor` routes with arrows/Enter/Esc; bell shows audit entries if `can('audit.view')` else "Nothing new."
**R7 Error wiring**: `PageBoundary` (500), `NetBanner` (offline), `onAction` map (home = `homeFor(perms)`, back, login, landing, switcher, account, retry via key). **Error pages have no logo and no decoration**: code (or the word Offline), title, one sentence, buttons (`ErrorPage.jsx` is shared). Accept: 401/403/404/423/429/500/offline all appear inside the shell (401 without it); suspended SACCO = 423 on every page except `account` and `my-settings`.
**R8 Public pages** (`public-*`): landing (3D hero, reveals, menu button on small screens), login (show/hide password), join, register, verify, forgot, reset. Every field in `Field`; submit disables while sending.
**R9 Account settings + photo viewer**: `POST /auth/change-password` (sessions end, go to sign-in), log out everywhere, photo viewer dialog (Esc/outside closes; upload device-only and labelled).
**R9b My settings** (own sidebar item, last, for every role; route `my-settings`): `MySettings.jsx` = `<AppearanceCard />` full width + a card linking to `/account`. `main.jsx` imports `nexora.css`, `nexora-2.css`, `tailwind.css` and calls `applyAppearance()`. **The look is per person**: `syncAppearance(user.id)` in `SessionProvider` after sign-in and restore, `syncAppearance(null)` after sign-out, `watchAppearance(() => user.id)` for other tabs; head script in `index.html` using `nexora.lastUser` and the same key `nexora.appearance:<userId>` and the dark list (ink, midnight). Switching circle never changes the look. Accept: Member picks Midnight, signs out, SACCO admin signs in and is still Cream, Member signs back in and has Midnight. Ten themes (Cream, Sage, Saffron, Terracotta, Teal 2, Ocean, Rose, Slate, Ink, Midnight), six fonts, three sizes, preview, Reset. Every word, icon and button visible in every theme (Lighthouse Accessibility in Cream, Saffron, Ink, Midnight: no contrast warnings; shell, drawer, switcher, bell, palette, photo viewer use tokens so popups are dark in dark themes). Print is black on white (do not override the print block).
**R10 Hand-in**: registry lists `account`, `my-settings`; public pages tested at their URLs with `VITE_MOCK=1`.
