# AI README: SAM (money and loans)

Give this file to your AI assistant together with `docs/frontend/COMMON-SETUP.md` and `docs/frontend/03-sam.md`. The AI must follow it exactly, must not invent scope, and must not touch files that are not Sam's. If something is ambiguous, it picks the sensible default and states it in the hand-in.

## 0. Project in one paragraph
NEXORA is a SACCO savings and loans app. Backend: Flask + Postgres (exists). Frontend: **React 19 (JavaScript) + Tailwind CSS v4 + Vite** in `frontend/`. The prototype (https://claude.ai/artifact/SPDZB7PDFbRt9wDJ3cvxH7, `docs/frontend/prototype/`) is the visual and behavioural reference (`requests.js` is the Deposit/Withdraw/Requests reference). Screenshots: `docs/frontend/images/`. Human docs: `pdf/NEXORA-Frontend-MASTER.pdf`, `pdf/03-Sam.pdf`.

## 1. Non-negotiable rules
1. No AI slop (no emoji, decorative logos, lorem ipsum, purple gradients, filler). 2. Units rem/%/vw/fr/clamp(); bare px only for 1px borders and shadows; never `w-[300px]`; check 375/768/1280, no sideways scroll (wide tables scroll inside `.table-wrap`). 3. Every list/card has loading, ready, empty, error (with Try again). 4. No raw errors: everything through `describe()` and `ErrorBanner` / `Field` / `ErrorPage`. 5. Permissions never role names. 6. **Money in minor units** on the wire (`toMinor`, `kesFromMinor`), no float maths on money; **one `reference` per submit** created when the form opens (`newReference()`), reused unchanged on every retry, replaced only after success. 7. No hex colours in `className` (tokens: `bg-cream text-ink text-muted text-teal border-teal-2 text-err font-serif`; shared classes `glass btn chip seg banner table-wrap kv rules field`). 8. Real buttons with hover/press/focus/disabled; smooth motion; Back buttons only on drill-ins (ledger, loan detail), never on menu pages. 9. Shared files read-only (`src/lib`, `src/components`, `src/mocks/data.js`, `src/styles/nexora*.css`, `tailwind.css`, `src/dev` except registry, `dev.html`, `vite.config.js`); report bugs to Collins. 10. Work in the harness (`/dev.html`) with mocks; never wait for Ryan or Neo.

## 4. Who sees what (permissions, from `lib/perms.js`)
- **Member** (`savings.request`): Overview (member version), My savings, Deposit, Withdraw, Loans (own + Request). 
- **Staff are SACCO pages only**: loans officer, finance officer, secretary and SACCO admin have **no My savings, no Deposit, no Withdraw** and their Overview is the SACCO's (no "My account" switch). Typing `/savings`, `/deposit`, `/withdraw` as staff = 403 page.
- Finance officer and SACCO admin (`savings.post`): Accounts, Post money, **Requests**. Loans officer: Approve/Reject. Finance: Disburse/Repay. Secretary: read only. Platform owner: none of your pages (403).

## 5. Tasks and acceptance
**S1 Overview, SACCO version** (`money-01`): used when `can('report.view')`. Four count-up stat tiles (`countUp`), savings line chart (`renderLine`), deposits-vs-withdrawals bars, loan-book donut, "Waiting for you" rows that are clickable (`navigate('/loans',{open:'loan:2045'})`; Loans reads `takeOpen('loan')`). Finance/admin tile "Member requests waiting" opens `/requests`. API `GET /admin/saccos/<id>/reports/summary` + loans list. No history = empty state "No history yet.", never made-up data.
**S2 Overview, member version** (`money-02`): balance ring (`renderRing`), My loan progress, next repayment, recent activity. Data `GET /savings/accounts/me` + own loan.
**S3 My savings (members only)** (`member-10`): balance, 12-month chart, transactions with Load more, filter chips, and a card "Add or take out money" with buttons Deposit and Withdraw (`navigate('/deposit')`, `'/withdraw'`). Shown only when `can('savings.request')`. No deposit form here.
**S3a Request API + mock** `src/api/requests.js`: `createRequest(saccoId,{kind,method,amount,phone|bank_name+account_ref,reference})` = `POST /savings/requests` (amount via `toMinor`); same `reference` twice returns the first row; withdrawal above balance throws 409 `INSUFFICIENT_FUNDS`. `listMyRequests(saccoId,kind)` = `GET /savings/requests/me?sacco_id=&kind=`. `listSaccoRequests(saccoId,status)` = `GET /savings/saccos/<id>/requests?status=`. `confirmRequest(id,reference)` = `POST /savings/requests/<id>/confirm` (409 `REQUEST_ALREADY_DECIDED`, 403 `OWN_REQUEST`, 409 `INSUFFICIENT_FUNDS`). `rejectRequest(id,reason)` = `POST /savings/requests/<id>/reject`. Mock keeps module memory seeded from `paymentRequests` in `mocks/data.js`. Item shape: `{id,sacco_id,membership_id,email,kind,method,amount_minor,phone,bank_name,account_ref,reference,status,reject_reason,decided_at,created_at}`.
**S3b Deposit page** (`member-01..04`, `member-09`): 12-col grid; left card the form, right card "How to pay" (changes with method), full-width History. Form: `.seg` switch **M-Pesa | Bank** (keep typed amount when switching), Amount (KES, `parseAmount`), M-Pesa: phone you paid from; Bank: bank name + reference on receipt; button Send deposit request ("Sending..." and disabled while in flight); note "This sends a request only...". Validation (message under field, focus first bad, send nothing): amount > 0 `Enter an amount greater than zero.`; phone `/^(?:\+254|254|0)([17]\d{8})$/` after removing spaces/dashes `Enter a Safaricom number like 0712 345 678 or +254 712 345 678.`; bank name >= 2 `Enter the name of the bank.`; reference >= 3 `Enter the reference from your bank receipt.`. Accept `0712345678`, `0712 345 678`, `0112345678`, `+254712345678`, `+254 712 345 678`, `254712345678`; show `0712 345 678`. Pay-in details are sample values from `payIn` in `mocks/data.js`, labelled as sample. Network failure: keep form, banner "We could not confirm that went through. Press Send again; it will not be sent twice.", same reference. Success: green banner **"Deposit request sent. An officer will confirm it and it shows in My savings."**, form empties, smooth scroll up, new row first in History with Pending chip. History table (When, Method, Amount, Details, Status) with chips Pending (warn), Confirmed (up), Rejected (bad + `Reason: ...`), "N pending", empty "You have not sent a deposit request yet.", Load more.
**S3c Withdraw page** (`member-05..08`): same structure; adds **Available balance** tile; Amount must not exceed balance, field message `You can withdraw up to KES 186,400.` (also handle server 409); M-Pesa phone to receive, or Bank name + Account number (digits 6-20: `Enter your account number, 6 to 20 digits.`); right card "What happens next"; banner **"Withdrawal request sent. An officer will confirm it and it shows in My savings."**; `kind:'withdrawal'`; no balance = "You have no balance to withdraw." and Send disabled.
**S3d Requests queue** (`requests-01..06`, `savings.post`): one glass card, `.seg` filter Pending (n) / Decided; table Member, Type chip, Method, Amount, Details, Requested, Decision. Pending rows: **Confirm** (new reference, disable row while sending, banner "Deposit of KES 12,000 confirmed and posted to Member 3's account.", row moves to Decided) and **Reject** (opens a reason field; empty = `Write a reason before you reject this request.`; success banner "Request from Member 3 rejected. They can see your reason."). 409 `INSUFFICIENT_FUNDS` = red banner, stays Pending; 409 `REQUEST_ALREADY_DECIDED` = "Someone already decided this request." + reload; the officer's **own** request shows chip "You cannot decide your own request" and no buttons. Empty texts: "No requests are waiting. New member requests appear here." / "No decided requests yet." Rules strip at the bottom. Phone: table scrolls inside its box.
**S4 Accounts + ledger** (`money-05/06/09`): searchable list (`GET /admin/saccos/<id>/accounts`), row opens `LedgerPage` with **Back to accounts**; filter chips, StatusChip, Load more; Reverse (`POST /savings/transactions/<id>/reversals`, reason dialog, new reference); already reversed = red banner with the server sentence.
**S5 Post money** (`money-07/08`, `error-09`): account search, Deposit/Withdrawal, amount, note; validation under fields; `POST .../deposits|withdrawals {amount,reference,note}`; "Posting..."; network failure keeps form and reuses the reference; 409 `INSUFFICIENT_FUNDS` banner. Pressing twice posts once.
**S6 Loans** (`money-10..13`): list with status chips (Waiting, Approved, Disbursed, Repaid, Rejected; `?status=`, client filter until Neo's change merges); member Request a loan (`POST /loans/saccos/<id> {principal,term_months}`); detail (**Back to loans**) with decisions timeline; `loan.approve` Approve/Reject with reason (`POST /loans/<id>/decisions`; 403 `LOAN_SAME_OFFICER` = "A different officer must give the second approval."); `loan.disburse` (`/disbursements`, 409 `LOAN_NEEDS_APPROVAL`); `loan.repay` (`/repayments`).
**S7 Reports** (`money-14`): summary tiles, sortable member-activity table, period filter, Print (shared print block makes it black on white; only hide buttons/filters in `sam.css`).
